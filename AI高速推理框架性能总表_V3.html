2、后续计划

（1）以“RTX 5090 × GR00T N1.7 × NVFP4 混合精度”作为第一个优化场景，开始后续方案部署。

（3）在其余需要优化的场景中测试该初步自动化部署方案，并在测试过程中不断完善。

（4）最终产出为若干部署好的场景，以及该自动化部署方案。

Triton Tiled GEMM：按固定矩阵形状设置 tile、warp 数与执行参数。
QKV／RoPE Fusion：把投影、QKV 拆分与旋转编码并入专用核。

Small-M GEMM 融合：动作专家小矩阵乘在同一 Triton 核内完成 gate 乘法及 residual 加法，直接写回结果。

GGML CUDA Operators：用 CUDA 后端执行投影、注意力和激活算子。

Scratch／Graph Cache：复用计算上下文与分形状图缓存，减少重复构图和分配。

Single-GGUF Packaging：将视觉塔、语言骨干与动作头封装进同一 GGUF，加载时识别架构并统一构建推理路径。
FoldQuant Integer Nodes：以激活变换和整数 GEMM 两类自定义 GGML 节点接入 CUDA，W8A8 路径采用 INT32 累加。
Hadamard＋SmoothQuant：离线折叠缩放并旋转权重；运行时对激活做块旋转和逐 token 动态量化后进入整数 GEMM。
Attention-layout Epilogue：支持的 GEMM 尾处理直接写入 Q/K/V 所需布局，并可合并 residual，省去额外转置与复制。

GGML CUDA／FlashAttention：矩阵运算交给 GGML CUDA；视觉模块可选融合注意力。
GGUF Quantized Weights：保留加载的量化矩阵类型；非线性算子按自身实现计算。
Prefix K/V Reuse（Pi0.5）：前缀图产生逐层 K/V，供动作专家各去噪步复用。
Persistent Workspace（Pi0.5）：保留计算图与 allocator，重复推理复用已分配内存。
分组件 GGUF 装配：Pi0.5 分策略与视觉投影器文件；GR00T 再拆分 Qwen3-VL 骨干、视觉投影器及动作头。
形状驱动图复用（Pi0.5）：以图像 token 数和文本长度判定计算图是否可复用；形状变化才重建图及工作区。
llama.cpp 特征桥接（GR00T）：由 llama.cpp／mtmd 执行截断到 16 层的 Qwen3-VL 骨干，将隐藏特征交给独立动作图。

PhyAI量化 Runner 调度
分模块 CUDA Graph：视觉、语言和动作 Runner 分别准备固定形状执行。
Shape Bucketing：按 batch／prefix 长度分桶，复用相应图和元数据。
FlashInfer Attention：通过统一后端接口调用高性能注意力实现。
Policy-driven Low Precision：按策略文件匹配层，选择 W/A 精度及低精度 GEMM 核。
Paged KV Pool：LLM Runner 写入共享 KV 池，动作专家读取前缀缓存。
Static Attention Buffers：缓存后端持有定形缓冲，每次推理原位更新索引元数据。
Kernel Policy YAML：用同一规则同时约束量化范围、W/A 位宽和执行核；Pi0.5 W4A16 预设保留视觉及输入输出头。
Layer／Kernel Catalog：模型层经统一目录匹配 FlashInfer、Humming 等实现，避免在模型 forward 中写死某个低精度核。
Full-loop Euler Graph（Pi0.5）：将 N 步“专家前向＋Euler 状态更新”展开进一张 CUDA Graph，以一次 replay 完成整段动作去噪。
AdaRMS Modulation Tables：固定 schedule 的时间 MLP 与各层调制提前投影存表；图内按步索引，移除重复调制 GEMM。
APXInf／APXinf-robo分层 执行 封装 单步
CUDA Graph Replay：Runner 准备 graph／eager 计划，执行时绑定新输入。
GEMM／Attention Autotune：准备期可按设备调优并缓存方案；默认复用已有配方。
CUDA／CUTLASS 融合算子：以模型无关 CUDA API 组合定制核与库函数。
BF16／FP8／INT8 路径：按设备分别启用静态 FP8 或动态 INT8 等模型变体。
Bounded Plan Cache（Pi0.5）：形状改变时替换旧计划，避免多个大工作区同时驻留。
固定时间嵌入（Pi0.5）：加载时准备时间表资产，重复推理直接使用。
PreparedInference（Pi0.5）：准备阶段完成分配、预热、调优及图捕获；相容请求热路径只绑定输入并执行准备好的计划。
Precision-specific Blocks：Pi0.5 共用模型运算顺序，由 BF16／FP8／INT8 Blocks 各自封装物理布局与精度专用融合。
Shifted Action Warm-start（可选）：平移上一个动作块并重复末端补尾，再与新高斯噪声混合，作为下一次去噪的初态。
Partial Flow／One-step（可选）：从较低噪声时刻开始积分，并可只走一步；改变原始采样过程，须单独比较质量。
EmbodiInfer架构 模型 概览
torch.compile／Inductor：对受支持的原生模型编译生成核；并非所有量化配置并用。
CUDA Graph Capture：按 batch 桶与步数缓存单步或整段去噪图。
Triton Attention／Fusion：融合归一化、RoPE 与门控激活等相邻操作。
GPU-aware Quant Profiles：按卡选 FP8／INT8／NVFP4；4090 Pi0.5 FP8 为仅权重路径。
Prefix K/V Reuse：同一观测仅编码一次，所有去噪步共享前缀 K/V。
Static Buffers／Pointers：重放复用固定输入与参数地址，保留图和工作区。
LoopGraph／SdeLoopGraph：把完整积分捕获成一次重放；SDE 图还包含逐步噪声注入及 RL 所需轨迹记录。
Refit＋Version Commit：原位更新权重而保持参数地址；提交新版本前刷新派生状态，使已捕获图继续使用。
Prefill／Denoise 双流（可选）：异步负载下重叠下一批编码与当前批去噪；用独立内存池协调分配，默认关闭。
expand_prefix 多候选复用：将一次编码的 PrefixState 广播给同一观测的多个动作候选，避免 best-of-N 重跑骨干。

“独特”指机制细节或有辨识度的工程组合，不代表首创
