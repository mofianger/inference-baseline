# RTX 5090 × GR00T N1.7：FP8 / NVFP4 Baseline

整理日期：2026-10-25。本页复用 2026-10-23 的已测结果，没有新增 GPU Run。完整外部清单见 [V3 总表](README.md)，可机器读取的数据见 [baseline-data.json](baseline-data.json)。

本 Setting 的 Recipe、配置和 Run 映射见 [5090-groot-n17-setting.json](5090-groot-n17-setting.json)；这是描述性索引，不是 CLI 自动解析配置。

**当前主 Baseline：FlashRT FP8 mean 14.418 ms；FlashRT NVFP4 混合精度 mean 8.974 ms。** 两条均已适配本仓库相同三视角 model-only 协议，并保存逐调用数据。它们是已测的起点，不代表所有引擎的性能上限，也不表示通过数值精度验收。

## 固定 Setting 与比较规则

| 字段 | 本仓库主 Baseline 约定 |
|---|---|
| 平台 | 单卡 RTX 5090，SM120；具体软件、驱动、二进制 hash 见原始 Run |
| ModelSpec | `gr00t-n17-3b-base-v1`；`nvidia/GR00T-N1.7-3B` base，非 LIBERO 微调 |
| checkpoint revision | `2fc962b973bccdd5d8ce4f67cc63b264d6886495`；完整资产哈希见原始 summary |
| Protocol | `groot-n17-b1-v3-model-only-v1` |
| 工作量 | B=1；3 路有效 RGB、每路 256×256；4 步去噪；H40、A132；embodiment 24 |
| 计时输入 | GPU 上已预处理的 patch tensor、token IDs/mask、grid、state 和显式公共初始 noise；在 learned embeddings 之前 |
| 输出 | GPU 上完整 normalized action `[1,40,132]` 完成 |
| 计时 | `sync → start → adapter.infer → sync → stop`；同步 CPU wall latency |
| 包含 | learned embeddings、backbone、状态编码、全部去噪、内部拷贝/metadata 传输、CPU 调度及完成同步 |
| 排除 | 原始预处理、外部 H2D/D2H、初始化/校准/编译/capture/warmup、机器人动作反归一化 |
| 共享测试集 | `datasets/groot-n17-v3`；manifest SHA256 `562a86fc238ca10adcc2b623be09bf796b74f1403fbdd5ab6f6d1785335c2297` |
| 校准与评估 | 1 个合成校准样本 + 4 个合成评估样本；每项 10 次预热、100 次测量；初始噪声固定共享 |
| 精度验收 | `accuracy_gate=not_configured`；对官方 eager BF16 reference 报误差，不接模拟器 |

FP8/NVFP4 是筛选 Recipe 的精度族。具体分模块 W/A、attention、KV、归约、输入输出 dtype 必须保留，不能将其简化成“全模型纯 FP8/FP4”。固定观察特征不得跨请求复用；同一请求的去噪步骤可复用 cross-K/V。

## 主表：本仓库可复跑的量化 Baseline

| 精度族 | Engine / Recipe ID | 分模块精度与执行 | Mean ms | P50 ms | P95 ms | 平均 MAE | 最大绝对误差 | 最低 cosine |
|---|---|---|---:|---:|---:|---:|---:|---:|
| FP8 混合 | FlashRT / `flashrt-groot-n17-sm120-fp8-v1` | 融合 FP8 backbone；action head 部分 FFN/QKV FP8，其余 BF16 混合；backbone/action CUDA Graph | 14.418 | 14.421 | 14.442 | 0.027798 | 1.300781 | 0.997901 |
| NVFP4 混合 | FlashRT / `flashrt-groot-n17-sm120-nvfp4-v1` | FP8 backbone；NVFP4 DiT 与 cross-K/V；其余 BF16 混合；backbone/action CUDA Graph | 8.974 | 8.976 | 9.014 | 0.028182 | 1.343750 | 0.998962 |

MAE 对 4 个唯一评估样本等权平均，排除 A/B/A 最后重复样本；比较完整 132 维归一化 action。当前协议下 NVFP4 mean 比 FP8 低约 37.8%，这是两个完整 Recipe 的比较，不是某一个 kernel 的独立加速效果。

两条使用 FlashRT commit `1fbe995089af4148bacd10ead61764d0aeb80f7a`、GPU_ARCH=120、独立校准缓存和仓库内 `third_party/FlashRT/.venv`。精确构建、二进制 SHA256 和环境以当次 Run 为准；后续安装目录可能已为 π0.5 重建，复跑须生成新的 Run，不能沿用历史数字。

2026-10-25 访问 [FlashRT 官方说明](https://github.com/flashrt-project/FlashRT/blob/main/docs/groot_n17_rtx_nvfp4.md)，其中仍列出 14.01/8.64 ms、双视角、4 步和 200 次 GPU median；页面未提供本仓库协议所需的全部资产 hash。访问的是浮动 main 页面，不代表锁定了新的上游提交。上述 B034 保留协作者的来源和措辞，本次未重跑。

上游还给出与 FP16 frontend 比较的 normalized-action cosine，以及与 official policy 比较的 relative-action cosine。两组参考实现和输出空间不同，均不能替换主表的 MAE 或作为本仓库精度通过依据。

视角、真实/合成输入、计时边界和统计量不同，因此不能用 14.01 对 14.418 或 8.64 对 8.974 的差值推断适配开销，也不能用该差值计算第三视角成本。LLM Qwen 的 NVFP4 吞吐同样不能证明该引擎能执行完整 GR00T action head。

## 复跑和新增配方

在服务器仓库根目录，确认 GPU 空闲、源码/二进制及配置版本后串行运行，替换唯一目录名：

```bash
bash scripts/run_5090.sh flashrt artifacts/<unique-groot-fp8-run>
bash scripts/run_5090.sh flashrt_nvfp4 artifacts/<unique-groot-nvfp4-run>
```

新增 EmbodiInfer / PhyAI 量化 Recipe 时：固定源 checkpoint，不修改共享 fixture；明确哪些模块用 FP8/NVFP4、哪些保留 BF16/FP32；指定校准数据和 seed；先核对输出与动态输入，再预热、检查图稳定性并计时。保留 MAE/RMSE/max-abs/cosine、逐调用延迟、实际 kernel/图路径及来源版本。若更改步数、动作长度、输入视角或输出空间，必须建立新协议分组。

本阶段仍是合成输入接入验证：未锁 GPU 时钟，100 次测量复用 4 个观测，无跨轮置信区间，无任务成功率，数值验收阈值仍为空。
