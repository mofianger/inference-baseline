# π0.5 / RTX 5090 首轮测试

状态：官方权重已完整校验、转换，OpenPI 参考实现及三个引擎的首轮运行已完成。正式延迟、数值误差、运行日志和来源清单见 [实测报告](../../reports/2026-10-23-5090-pi05/README.md)。未设置精度通过阈值。

## 固定协议

官方源为 `gs://openpi-assets/checkpoints/pi05_base`，保存于服务器 `/data/huggingface/openpi/pi05_base`。使用官方 base，不替换成 LIBERO/DROID 微调权重或第三方转换副本。下载清单固定 GCS generation，逐文件检查大小、CRC32C 及可用的 MD5，再记录 SHA256。全部完成后才生成 `verified-files.json`。

三路有效 RGB 视角，顺序为 base、left wrist、right wrist。输入是 GPU 上的 FP32 `[1,3,3,224,224]`、范围 `[-1,1]`；文本 token 为 int64 `[1,200]`，mask 为 bool。已归一化的 32 维状态按官方 tokenizer 离散化并写入文本，tokenization 不计时。10 步 Euler 去噪，公共 FP32 初始噪声 `[1,50,32]`，输出完整 normalized action tensor `[1,50,32]`。

计时覆盖 learned image/token embeddings、完整 prefix、全部去噪、内部布局转换/拷贝、CPU dispatch 和 GPU 完成同步。不含原始图像处理、外部 H2D/D2H、加载、校准、编译、capture、warmup、机器人空间反归一化。不允许跨请求复用观测特征。状态敏感性检查一起替换 state、tokens、mask；单独替换 state 不构成有效的 π0.5 检查。

5 个固定合成样本（1 calibration、4 evaluation），10 次 warmup，100 次测量。报告误差，无精度验收阈值，无任务成功率声明。

依据：[官方模型配置](https://github.com/Physical-Intelligence/openpi/blob/215abfb217dbac7d5f1273282331b9b1866c0479/src/openpi/models/pi0_config.py)、[官方采样器](https://github.com/Physical-Intelligence/openpi/blob/215abfb217dbac7d5f1273282331b9b1866c0479/src/openpi/models_pytorch/pi0_pytorch.py)、[状态 tokenizer](https://github.com/Physical-Intelligence/openpi/blob/215abfb217dbac7d5f1273282331b9b1866c0479/src/openpi/models/tokenizer.py)。三路全部有效是本 benchmark 的约定。

## 环境与权重

| 路径（服务器仓库内） | 用途 |
|---|---|
| `.venv-assets` | 官方权重下载、CRC32C 验证 |
| `third_party/openpi/.venv` | 官方转换和参考输出；Torch 2.7.1+cu128 / Transformers 4.53.2 |
| `third_party/EmbodiInfer/.venv-pi05` | 新建 π0.5 环境，LeRobot 0.5.1；独立于现有 GR00T 环境 |
| `third_party/phyai/.venv` | PhyAI；沿用已有引擎环境 |
| `third_party/FlashRT/.venv` | 仓库内 FlashRT 构建；不使用 `/data/5090-machine/FlashRT` |

OpenPI 完整 `uv sync` 会引入 MuJoCo。本轮使用模型所需依赖，JAX 只在 CPU 上用于转换。必须安装支持 SM120 的 Torch CUDA 12.8 wheel；默认 PyPI 的 Torch 2.7.1 wheel 在此服务器上无法执行 5090 kernels。官方 Transformers replacement 只应用到 OpenPI 的独立环境。

已安装依赖快照：[OpenPI](../../requirements/pi05-openpi-5090.txt)、[EmbodiInfer](../../requirements/pi05-embodiinfer-5090.txt)。安装时需要 PyTorch CUDA 12.8 wheel index，之后用 `scripts/setup_openpi_model_env.py` 应用官方补丁；不要将 OpenPI 补丁复制进其他引擎环境。OpenPI 与 LeRobot 0.5.1 模型的 811 项有效参数名称、形状已逐项预检一致，但这不能代替实际权重加载和输出校验。LeRobot 默认保留完整 vision/projector 为 FP32，与 OpenPI 的部分 FP32 策略不同，会如实记录为 Recipe 差异。

`scripts/convert_pi05_official.py` 复用固定 OpenPI 提交的转换函数；显式构造 base 配置，不借用微调训练配置。FP32 构造与导出避免先加载进 BF16 参数造成不可追踪舍入。审计缺失和多余参数；删除 action sampling 不使用的词表输出头，保留严格加载的输入 embedding。转换目录为 `/data/huggingface/openpi/pi05_base_pytorch_fp32`，附源文件哈希及转换来源。

## 计时适配

| 引擎 | 路径 | 已执行的检查 |
|---|---|---|
| OpenPI | 官方 eager `sample_actions`，显式 noise | 811 个有效参数严格加载、冻结参考输出 |
| PhyAI | inline `Engine.step(PI05Request)` | vision、prefix buckets、完整 Euler 图及动态输入检查 |
| EmbodiInfer | `Pi05Runtime.request` 完整请求图 | 严格加载、完整请求图、动态输入检查 |
| FlashRT | 更新 GPU embedding/mask/RoPE，`Pi05Pipeline.forward` | BF16/FP8/NVFP4 完整图、校准、动态输入检查 |

FlashRT 公共 `infer()` 不直接作为本协议的计时入口，因为它处理 CPU 图像且返回反归一化后的 CPU action。Adapter 每次都根据输入 token 计算 embedding，更新有效 prefix 长度及 decoder RoPE，写入 GPU buffer，并读取完整 GPU action。归一化 stats 不参与这条路径。

## 执行

本机环境首次准备后，FlashRT π0.5 还需执行 `bash scripts/build_flashrt_pi05.sh` 开启 SM120 SKINNY/NVFP4 kernels，并在其 venv 安装 `ml-dtypes==0.5.4`。PhyAI 配置显式使用 256 MiB FlashInfer workspace；CLI 会将当前 venv 的 bin 加入 PATH。完整 Recipe 说明见 [FlashRT](../../recipes/flashrt/pi05.md)、[EmbodiInfer](../../recipes/embodiinfer/pi05.md)、[PhyAI](../../recipes/phyai/pi05.md)、[OpenPI](../../recipes/reference/pi05.md)。

从服务器仓库根目录运行。不要在其他人在使用 GPU 时启动计时。

```bash
git pull --ff-only
.venv-assets/bin/python scripts/download_pi05_official.py --output /data/huggingface/openpi/pi05_base
third_party/openpi/.venv/bin/python scripts/check_pi05_environment.py
.venv-assets/bin/python scripts/run_pi05_suite.py --output results/<unique-pi05-run-id>
```

Suite 依次转换、准备固定测试集，再以不同 Python 进程运行参考、PhyAI、EmbodiInfer、FlashRT BF16/FP8/NVFP4。BF16 配置中的 precision 字符串是上游必填选择器；实际通过 `use_fp8=false` 与 `FVK_PI05_RTX_FORCE_BF16=1` 禁用 FP8，运行时记录实际开关。若下载仍在进行，可添加 `--wait-for-download`；它只在完整校验清单出现后继续。每个阶段日志和返回码写入 `suite.json`，失败的 engine 不作为实测结果。不得启动两个下载进程写同一权重目录，也不得并发运行两个 GPU benchmark。

单项重试使用新的输出目录：

```bash
third_party/FlashRT/.venv/bin/python -m inference_baseline.cli run \
  --config configs/5090/pi05-flashrt-fp8.json \
  --dataset datasets/pi05-base-v3-v1 \
  --output results/<unique-retry-id>
```

尚未验证的其他候选：FlashRT 不同 prefix/decoder 混合精度组合；EmbodiInfer 独立 prefix+loop 图、通用融合算子及量化 MLP；PhyAI 不同 vision dtype、kernel policy 和量化配置。不得直接把 Thor/4090 的专用 kernel profile 标成 5090 已支持。首轮实际跑通后再按数值检查与硬件能力扩充配置。
